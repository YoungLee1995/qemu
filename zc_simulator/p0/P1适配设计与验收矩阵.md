## 2. 共享 DDR 与访问视图

沿用 `sm_regs.h` 的 DDR0 `[0x20000000,0x60000000)` 1GiB 和 DDR1 `[0x4000000000,0x8000000000)` 256GiB 地址跨度。每卡每区域一个独立稀疏 memfd，`ftruncate` 到跨度，两侧 `MAP_SHARED`，页面按实际触达分配；不预触达 256GiB。宿主资源不足应报告失败，不静默回退第二份私有 DDR。若采用缩小容量实验，必须单列 profile、校验镜像及控制区是否仍落在范围内。

区域 FD 内偏移为 `device_address - region_base`，边界校验使用 `len <= size && offset <= size-len` 防溢出。`make_mems` 构造选定 DDR 的共享 `abstract_mem_t` 实现；需同时实现 CPU 直接页访问所需的 `contents` 和 load/store，使固件加载、MMU、`sm_box` 都看到同一 backing。L1 每核 8MiB、MCU SRAM 和 MMIO 保留现有归属。

| 访问者 | 地址转换与接入点 |
| --- | --- |
| firmware/dispatcher、MCU/NPU CPU | 原模拟物理地址译码 → 新共享 DDR 设备，原 remap 保留 |
| NPU box/local DMA | 原描述符布局/地址处理 → simif/mmio/DDR；本地操作不走 socket |
| Host BAR、目标 P2P | QEMU BAR/桥窗口/inbound 权限与范围检查 → 区域偏移 → 同一 FD |
| HDMA 本地端 | 合法设备地址 → 区域偏移；对端由 PCIe 公共访问服务处理 |
| NPU 外部 DMA | raw 地址及模式分类 → QEMU outbound/Host IOMMU 或 peer 路由；返回数据再写本地 DDR/L1 |

QEMU 创建并拥有 FD，经 Unix socket `SCM_RIGHTS` 交付；后端核对 fstat 大小、区域数量/重叠、card/session，映射成功后回 `MEM_READY`。连接失败关闭新收到的 FD。正常退出先停访问，再 unmap/close；断连时先停止新提交与在途写，再释放。reset 首期销毁并重建后端，旧映射/旧写终止后才重用或清零 DDR。缓存一致性在功能模型按宿主共享映射实现，发布任务/完成使用 release/acquire；不模拟硬件 cache 性能。

## 3. 控制消息及线程所有权

P1 控制面采用本地 Unix `SOCK_SEQPACKET`。协议使用显式小端编码，禁止直接传 C struct；每帧头 48 字节：magic u32、version u16、type u16、payload_len u32、card_id u32、session_id u64、epoch u64、request_id u64、flags u32、reserved u32。version 初值1；session 每次连接重新分配，epoch 每次 reset 增加；request_id 在会话内不重复。magic 建议固定 `0x5a435030`，属于内部协议，不能写进驱动可见 ABI。

首期 payload 最大 64KiB，含头的整帧一次发送；长度、保留位、能力不符直接报协议错误并断连，禁止截断后执行。大 DMA 按公共服务分片，父请求聚合完成，分片成功不等于父任务完成。每笔请求恰好一次 terminal reply；错误以独立 status 携带，不用空数据表示成功。默认连接/请求超时各 5秒/30秒，可配置，超时进入 quiesce；不能仅删除表项后继续允许旧写。

| 消息 | 含义/必要字段 |
| --- | --- |
| HELLO/HELLO_ACK | 双向协商 version、card、session、能力、最大帧；协商失败不启动核 |
| MEM_SETUP/MEM_READY | 区域 base/size/FD index，附 FD；后端验证及映射确认 |
| START/SOFTWARE_READY | 固定镜像配置摘要；软件实际初始化后发布 ready，连接建立不能冒充 ready |
| REG_WRITE/REG_RESULT | QEMU 所有 PCIe 寄存器的异步后端代理；地址/宽度/字节使能/值；结果含 status |
| IRQ_REEVALUATE | mailbox 状态变化提示，可合并；接收方重新读权威状态，不能按提示次数重复完成 |
| DMA_READ/DMA_WRITE/DMA_RESULT | 引擎、父ID、地址域、地址、长度、分片偏移、数据或状态；QEMU 从绑定 card 确定 function，拒绝伪造 requester |
| QUIESCE/QUIESCED | 停新请求，排空/取消到旧写已不能生效；明确 outstanding 计数 |
| RESET/RESET_ACK | 旧代 quiesce 后重建软件与状态，ACK 不代表软件已 ready |
| STOP/STOPPED、ERROR | 生命周期停止确认/诊断；任务完成独立于 STOP |

socket I/O 在非阻塞事件源/线程中收发，仅入队；后端模型线程在 hart step/tick 边界处理队列和 ECLIC。NPU 等外部返回时保存 continuation、busy 和在途计数并让调度线程继续推进消息，禁止在 `sm_box` 同步等待 socket。QEMU 数据事务在其内存/设备线程所有权规则内执行；跨线程投递到所属 AioContext/BH，不从任意 socket 线程操作 PCI 设备。

## 4. 同步寄存器读的落地选择

QEMU 普通 MMIO read 回调必须同步返回，不能在回调中等待跨进程 RPC，也不能把旧快照当真实状态。因此分两类处理：

1. QEMU 持有的 PCIe/HDMA/iATU 寄存器在 QEMU 本地完成同步读写。MCU 访问这些代理寄存器时由后端异步等待结果，消息泵继续运行。
2. mailbox 在 P1 改为**同一份共享寄存器 backing**：后端和 QEMU 的寄存器访问器都操作该对象，不建立第二套 bank 缓存。采用宿主进程间可用的无锁32位原子状态；启动检测 `is_lock_free`，不满足则拒绝该实现。STATUS 用 fetch_or/fetch_and，INTEN/DATA 用原子 load/store，SEND release 发布此前 DATA；核侧/Host读 acquire。IRQ 仍只由后端模型线程根据当前 pending & enable 更新。共享对象另带变更序号，事件仅负责唤醒，周期检查防止遗漏唤醒。

这保留后端对 MCU/NPU 本地通知与 IRQ 的管理，寄存器值有唯一共享对象。需要重构 `mailbox_t` 的存储访问器、重跑所有内部 mailbox 用例；不是在 QEMU 建寄存器镜像。字段布局、原子支持、SEND/INTEN/W1C 并发线性化与 DATA→SEND 顺序必须专项验收。仅承诺已验证的对齐32位访问；真实驱动若要求其他宽度/非对齐，先按硬件补契约。原 mailbox 实现对非法访问返回 false，新桥接不得静默成功。

尚未确认 Host BAR 映射前，此设计可用显式实验窗口验证；该窗口必须标为实验，不替代真实驱动兼容性。若硬件寄存器读还依赖核上动态动作，需重新设计可同步访问的权威状态或实现 QEMU 延迟事务机制，不能套用共享静态字段方案。

## 5. 生命周期与写入屏障

`DISCONNECTED → NEGOTIATING → MEMORY_READY → STARTING → READY → QUIESCING → STOPPED`；协议/启动错误进入 FAILED。只有 READY 接收任务。QUIESCING 停止新请求、取消未执行请求、等待已开始的写终止，核/引擎停止后确认。随后 epoch 更新、重建后端、状态初始化、再次软件 ready。

仅丢旧 epoch 响应不够：QEMU 已排队的写、后端 continuation、DMA 分片和共享页写都必须终止。断连无法协商时停止/回收旧后端并确认进程退出，撤销旧会话工作队列，在确认前禁止新代复用 DDR。数据写完成并具有 release 顺序后再发布完成/中断；mask 不得丢失硬件定义的 pending。reset 默认寄存器值仍需真实资料确定。

## 6. P1/P2 固定验收矩阵

以下均为待开发用例，不能计入本轮已通过测试。搬运输入固定 `byte[i]=(i*37+card_id*13+task_id)&255`，逐字节验证；局部范围前后各64字节 guard 保持 `0xA5`。选择长度 1、16、4095、4096、4097 与跨4KiB页范围；零长度是否允许按实际引擎定义，拒绝也须有确定结果。

| 编号 | 输入/动作 | 判据 |
| --- | --- | --- |
| P1-MEM | 固件写→Host读，Host写→MCU/NPU读；不同card相同offset | 同一backing数据一致；异卡不互见；边界/溢出失败且guard不变 |
| P1-MBOX | DATA→SEND，先SEND后INTEN，pending时mask/unmask，W1C、重复提示 | 值与IRQ关系正确，无双状态、无重复完成；内部旧用例通过 |
| P1-SVC | 实际软件ready后连续两笔以上既有任务，再STOP | ready来自核初始化；任务后仍服务；STOP才退出，非法任务不执行 |
| P1-FAIL | 协议版本错、FD大小错、断连、ready超时、空闲reset | 明确失败，资源释放；新代重新ready；无永久等待 |
| P2-H | 仅HDMA双向Host搬运 | 原驱动合法描述符；数据/guard/完成和错误状态正确 |
| P2-N | HDMA从未启动，原NPU DMA指令双向Host访问 | 原布局/stride保留；外部在途busy/fence不提前结束 |
| P2-IOMMU | 非恒等IOVA，跨页，不映射，只读写入，撤销 | function DMA AddressSpace真实检查；失败无越权写，无假完成 |
| P2-MIX | HDMA→HDMA、NPU→NPU、HDMA→NPU、NPU→HDMA | 原软件依赖及最终输出一致；不暗中启动另一引擎 |
| P2-RESET | 在途读写与reset/断连交错后重启任务 | 旧写不能污染新代；父请求恰好一次终止；重启任务正确 |

trace 必备字段：timestamp、card/BDF、session、epoch、task_id（可关联时）、engine、parent/request_id、raw/device/translated地址、地址域、length、status、完成/数据可见顺序。请求ID不冒充业务任务ID；无法关联时显式未知。Host IOMMU与P2P的路径验证、真实DMA描述符原始字节及预期错误码，分别在实际接口冻结后补充运行样例。

## 7. P0 收敛后的实施边界

P0 基线与适配设计已完成。本文中“待补/待确认”指对应 PCIe 功能在 P1/P2 编码前需要核对的字段，不指等待另一套 runtime、QEMU 镜像或独立 Host 驱动。现有 simu 内部 runtime 直接保留；Zebu demo 和寄存器手册作为 PCIe 参考，stage1 作为来宾测试及连接基线。材料未定义的字段明确记录软件配置和适用范围，不猜测成硬件已确认值。后续如获得独立驱动，再扩大兼容验收。
