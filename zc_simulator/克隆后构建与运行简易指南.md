# 克隆后构建与运行简易指南

目标：仅克隆本 QEMU 仓库，使用已附带的 simu 二进制包，完成 x86 Linux 双卡/八卡多卡互访实验。无需 simulator 源码或 RISC-V 编译器。

## 1. 准备环境

推荐 **Ubuntu 22.04 x86-64**。已发布 Spike 依赖 Boost Regex 1.74、ICU 70 和 OpenMP，这与 Ubuntu 22.04 的软件包匹配。其他发行版需自行解决相同 SONAME 的动态库，不能直接把 ICU 其他大版本软链接为 ICU 70。

```bash
sudo apt update
sudo apt install -y \
  git build-essential ninja-build pkg-config \
  libglib2.0-dev libpixman-1-dev zlib1g-dev libfdt-dev \
  python3 python3-venv python3-pip curl ca-certificates \
  libboost-regex1.74.0 libicu70 libgomp1 libstdc++6
```

**当前仓库 QEMU 构建要求 Python >= 3.12**，Ubuntu 22.04 默认 Python 3.10 不够。已有 Python 3.12+ 可直接使用；否则可用 uv 安装独立 Python，不替换系统 Python：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
uv python install 3.12
```

以下构建命令使用 `uv python find 3.12` 获取路径。若使用已有 Python，把 `--python=...` 改为它的实际路径即可。预编译 Linux runner 使用系统 `python3` 即可，3.10 可以运行。

## 2. 克隆仓库并检查运行包

```bash
git clone --branch master https://github.com/YoungLee1995/qemu.git
cd qemu
git submodule update --init --recursive

ls -l zc_simulator/simu/current
ldd zc_simulator/simu/current/bin/spike
python3 zc_simulator/p5/run_linux.py --runtime prebuilt --prepare-only
```

`ldd` 不应出现 `not found`；最后一条应成功退出并打印证据目录。运行包已在 Git 中，无需另行下载压缩包。请使用保留软链接与执行权限的 Linux Git 工作区。

首次配置/子模块初始化可能联网。`--prepare-only` 这里只验证包，不编译 simu、不启动 QEMU。

## 3. 构建 QEMU

仍在刚克隆的 `qemu` 仓库根目录：

```bash
mkdir -p build
cd build
../configure \
  --python="$(uv python find 3.12)" \
  --target-list=x86_64-softmmu \
  --disable-docs \
  --disable-werror
cd ..

ninja -C build -j4 qemu-system-x86_64
./build/qemu-system-x86_64 --version
```

不需要 `sudo make install`。脚本直接使用本仓库 `build/qemu-system-x86_64`，不能用系统安装的普通 QEMU 替代，因为本项目增加了 PCIe endpoint。机器内存紧张时将 `-j4` 改为 `-j2`。

若提示 Python 包缺失，检查配置时的联网状态，查看 `build/config.log` 或 `build/meson-logs/meson-log.txt`；QEMU 会创建其构建 Python 环境。BIOS/ROM 使用仓库及正常构建提供的资源，无需重新编译整套固件子模块。

## 4. 运行双卡，再运行八卡

仍在 `qemu` 仓库根目录：

```bash
# 双卡：首次联调先跑这个
python3 zc_simulator/p5/run_linux.py --cards 2

# 八卡：覆盖 56 个有向卡对
python3 zc_simulator/p5/run_linux.py --cards 8
```

没有 simulator 源码时自动使用包内 Spike、firmware、MCU/NPU 镜像、管理服务、Linux 内核及来宾镜像，不再编译 simu 或 Host 驱动。若同级恰好存在 simulator 源码但只想使用交付包，加 `--runtime prebuilt`。

脚本自动启动 x86 Linux、加载驱动、启动各卡常驻 simu、提交任务并校验结果，结束后自动关机和回收。无需手动启动 Spike，无需 KVM，使用 TCG。它是自动测试入口，不停留在交互式 Linux shell。

终端检查项全部显示 `PASS`，最后打印：

```text
Evidence: .../zc_simulator/p5/evidence/linux-...
```

该目录 `results.json` 应有 `passed: true`；`linux.log` 应包含 `P5_BASE_PASS`、`P5_C_LIBRARY_PASS`、`P4_GUEST_EXIT=0`。双卡/八卡各卡普通任务期间都应保持单个 Spike 进程。

## 5. 接下来读什么

详见 [P0–P5 功能使用手册与工具链多卡互访指南](P0-P5功能使用手册与工具链多卡互访指南.md)：第一部分介绍 Host 驱动提交任务、simu runtime 执行内部 DMA、多卡访存、完成和错误获取。

**注意命令所在目录**：本简易指南是在克隆后的 `qemu/` 内执行，所以用 `python3 zc_simulator/...`。完整手册默认在它上一级的工作区执行，所以写 `python3 qemu/zc_simulator/...`，两者指向同一脚本。

该二进制交付包支持上述 P5 Linux 双卡/八卡入口。完整手册中 P0 独立构建、其他历史阶段验收及独立 Tensor 任务数据等入口仍有各自的源码/输入依赖，不是克隆 QEMU 后就能全部执行。

## 6. 为什么 Spike 没有超过 GitHub 100 MiB 限制

本次实际文件大小：

| 文件 | 大小 | 用途 |
| --- | --- | --- |
| 原始 `simulator/riscv-isa-sim/build/spike` | 217,935,184 字节，约 208 MiB | 开发调试版本，包含大量 DWARF 调试信息 |
| 交付 `zc_simulator/simu/current/bin/spike` | 11,449,448 字节，约 10.9 MiB | 移除调试信息后的运行副本 |

构建脚本复制文件后，对副本执行：

```bash
strip --strip-debug 运行包路径/bin/spike
```

它删除 `.debug_info`、`.debug_line` 等调试段，保留执行代码和运行所需内容；没有删减指令集、DMA 或 MCU/NPU 功能，也没有压缩成运行时需解压的程序。原始开发版本没有被 strip。

原始和交付版 Build ID 相同，本次额外检查 `.text`、`.rodata`、`.data` 内容 SHA256 相同；交付副本已通过先前无 simulator 源码目录下的八卡 Linux 测试。代价是交付副本不包含源码行级调试信息；开发机原始文件可继续用于调试。

交付的最大单文件是约 13 MiB 的 Linux 内核，因此没有超过 GitHub 100 MiB 单文件限制；整个运行包约 31 MiB。

本指南基于当前源码的构建要求及已有同机运行证据整理；未在本次编写文档时重新执行一遍全新 Ubuntu 系统安装和完整 QEMU 构建。
