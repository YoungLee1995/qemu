# P2 单卡软件功能闭环验收

日期：2026-10-28。本轮接续第二批 P2 实现，按原分阶段方案的单卡 Host 访问服务、两类 DMA、混合任务、恢复与实际计算结果完成收敛。当前工作区未提交，不创建或推送提交。

## 为什么上一轮没有关闭

上一轮有实质验收缺口：四组合使用 XOR 工作负载，尚未把原 Tensor 指令的输入和输出通过两类 PCIe DMA 联合验证；reset/断连虽有 P1 和 HDMA 证据，却缺 NPU 原 DMA 读写在途的逐项恢复矩阵。此外，统一测试把 `p2_full_exit` 固定写成 false，把全部 DWC 高级特性、物理 IRQ 编号和生产文件解析也混入退出条件，即使功能测试通过也无法关闭。

本轮没有用改布尔值代替开发。先补上述实质测试和可重复故障注入，再依据原方案明确阶段范围。`p2_full_exit` 的含义是**单卡软件功能 profile v1 的 P2 出口**；新增 `hardware_compatibility_exit=false` 独立记录未经确认的硬件兼容性。硬件未知字段不伪装成已确认，既有数值偏差也不改为通过。

## 本轮代码与验证补充

### 原 Tensor 四组合

P2 runtime 新增显式实验任务字段 `service+0x11c`（`c[71]`）：0 为原 XOR 搬运工作负载，1 为现有捕获 Tensor 工作负载。Tensor 模式长度必须为 `0x9200`，输出为 33792 字节。MCU 按输入/输出引擎组合处理实际长度，拒绝非法模式/长度。

使用原 `execute_tensor` 汇编（捕获指令 `0x8204000b`，原增强 fence）及既有 128 字节参数。Host 将现有 act/weight/scale/index 放入输入缓冲，经 HDMA 或 NPU 原 DMA 搬入 L1；NPU 执行原 Tensor，再经对应输出引擎返回 Host。四种组合均全量比较固定 standalone 结果，普通任务复用同一 Spike。此实验任务字段与生产文件 ABI 分别管理，未增加生产解析器。

固定 standalone 结果：`experiments/single_die_packet/run-20261027T100512-648188Z/moe/data/result_l1_spike.bin`，SHA256 `37121ee2cd6afaed02f18587ed683d6fb5d5c4a6cd3b078f682a77891fe7e015`。比较目标是证明 PCIe 接入没有改变既有模型结果；历史独立数学 golden 的 322/1122 BF16 不一致、最大绝对误差 1.0 仍是算子数值待办，不据此宣称数值精度关闭。

### 两引擎在途 reset 与断连

为避免靠时间碰巧命中窗口，在仅 qtest 可用的 BAR0 `+0x381080` 增加故障暂停位：bit0 NPU 外部读、bit1 NPU 外部写、bit2 HDMA 读、bit3 HDMA 写。正常 Linux/TCG 下该地址不提供暂停控制，不能改变生产运行；普通成功 DMA 不使用暂停。

每例先确认请求已被接收且未完成（NPU 共享槽 state=1 且方向正确；HDMA busy），再执行系统/device reset 或关闭常驻控制服务造成断连。reset/断连取消工作时清除暂停位。断连用新服务重连、分配新 backing；reset 通过 QUIESCE/reap/新 epoch 恢复。每例检查旧 PID 已回收、只替换一次后端、Host 输出无旧写、无假完成、恢复任务数据正确及没有重复完成通知。读/写×两引擎×reset/断连共 8 例。

这里的暂停提供确定的已接收未完成窗口，不能据此外推所有任意指令时刻的竞态或部分写原子回滚。跨页部分完成、通道停止、映射取消另有专项。未声明 PCIe FLR capability，因此不把尚未公开的 FLR 当本阶段已支持接口。

### 请求追踪

`p2_host` 交易返回事件增加 timestamp_ns、bus、channel、parent_id、address_domain、phase；HDMA 在 doorbell 分配父请求，分片共享同一 parent；NPU 代理使用原递增请求序号。trace 保留源 function、session、epoch、原设备地址、转换 IOVA 和 MemTxResult。业务 task/hart 尚未由真实协议携带，明确输出 null，不把请求号冒充任务号。phase=`transaction_returned` 只表示该交易 API 返回，不冒充整个任务完成。

## 关闭条件与保留差异

| 范围 | P2 软件功能出口判据 |
| --- | --- |
| 公共服务 | function DMA AddressSpace、真实 IOMMU 转换与权限、跨页与错误 |
| HDMA | 双向八通道、现有 demo 描述符子集、STOP/ABORT、MCU 本地 ISR、停止/重配 |
| NPU 原 DMA | 不依赖 HDMA 的 Host 双向访问；原队列/fence；可恢复错误与后续任务 |
| 混合任务 | 四种输入输出组合，XOR 与原 Tensor 均全量校验；常驻进程 |
| Host 文件协议 | 原 Host 驱动适配副本的 coherent IOVA、CRC32、result header/done 顺序与回读 |
| 生命周期 | 两类引擎读写在途 reset/断连、旧写终止、无假/重复完成、恢复任务 |
| 回归 | Linux Host、完整 P1 七组通过；源码/产物摘要固定 |

以下作为明确差异继续保留，不伪造硬件闭环：物理 MCU IRQ 号（内部 profile 为60）、硬件 NPU 通道错误 CSR（当前 per-hart 诊断接口）、未使用的 DWC VF/CFG/MSG/Atomic/ATS/remote 中断等高级特性、生产任务文件格式解析、独立数学 golden、FLR。后续出现实际驱动需求或硬件定义时在对应兼容性迭代补齐；P3 双卡/P2P 继续按原计划单列。
