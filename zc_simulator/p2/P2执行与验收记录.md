# P2 执行与验收记录

2026-10-28，内部软件功能仿真。准入依据是P1单卡功能闭环及已确认BAR属性。**本轮交付P2首轮可运行代码；完整P2未关闭。** 此记录区分真实搬运证据与尚未实现的硬件兼容项。

## 本轮开发内容

1. 在现有EP上增加默认关闭的P2能力，实现绑定源function的Host访问服务，使用`pci_dma_rw()`和真实QEMU IOMMU；限制Host RAM访问，拒绝MMIO/P2P误路由。
2. 实现8对HDMA通道、直接/本地链表提交、地址转换、每页推进、STOP/ABORT/W1C、通道禁用及function reset取消。
3. 实现Spike→QEMU共享访问代理；MCU内部寄存器与Host调试镜像访问同一份HDMA/iATU状态。两进程不重复持有控制器状态。
4. 将原NPU DMA实际访存接到显式外部窗口，保留原描述符、调度队列和增强fence；纯NPU模式不启动HDMA。
5. 用实际MCU/NPU程序执行四种输入输出组合，验证整段数据、顺序完成及连续任务复用进程；在真实Linux来宾加载工具链原Host驱动适配副本，用coherent IOVA搬运并接收MSI-X。
6. 增加统一顺序验收入口、逐组日志及manifest，并将完整P1回归列为本轮门禁。运行文件继续ignore。

## 验收证据

本次已构建当前QEMU、Spike及测试runtime，firmware沿用P1已有固定产物，随后固定源码与二进制，执行 `python3 qemu/zc_simulator/p2/run_all.py --skip-build`。该参数跳过前三项主构建，runtime及来宾测试仍重建。`p2_first_implementation_pass`要求P2三组与P1全部回归通过；`p2_full_exit`保持false，避免将功能子集当完整P2。

最终汇总：[all-1793168235607115248/results.json](evidence/all-1793168235607115248/results.json)，`p2_first_implementation_pass=true`、`p2_full_exit=false`。25项源码/构建产物SHA256与运行结束后的工作区逐一一致；生成证据不纳入Git。

| 验收 | 本次实际结果 | 证据目录 |
| --- | --- | --- |
| HDMA/Host IOMMU | 32项通过，含非恒等IOVA、超过4GiB IOVA、跨页、部分失败、只读/撤销/未映射、requester隔离、8个write通道、链表与停止 | `evidence/hdma-1793168235638529274` |
| 真实MCU/NPU | 30项通过，四组合、同PID、MCU代理、取消/reset/新epoch、reset后恢复任务、NPU故障无假完成 | `evidence/spike-1793168236353233257` |
| Linux工具链Host驱动 | 7项通过，5笔任务覆盖4种组合，每笔12345字节全量比较，实际coherent IOVA及完成MSI-X，同一个Spike | `evidence/linux-1793168239824099563` |
| 完整P1回归 | `p1_full_exit=true`，原七组全部通过，含5次Linux、会话/FD、恢复、BAR、内存、IRQ隔离、stage1 | `../p1/evidence/full-1793168257431946012` |

Linux本次输出 `P2_IOVA=ffe00000`、`P2_LINUX_PASS tasks=5 modes=4 coherent_iommu=1 msix=1`、`P2_GUEST_EXIT=0`。本组验证真实驱动分配的coherent IOVA；非恒等页表和权限故障由HDMA/qtest专项独立证明，不以启用IOMMU日志替代转换证据。

测试模式与实际路径：

| 模式 | 输入 | NPU内计算 | 输出 |
| --- | --- | --- | --- |
| 1 | 原NPU DMA：Host IOVA经outbound→L1 | L1逐字节XOR 0x5a | 原NPU DMA：L1→Host IOVA |
| 2 | MCU代理配置HDMA：Host IOVA→共享DDR；NPU本地DMA→L1 | 同上 | NPU本地DMA→DDR；HDMA→Host IOVA |
| 3 | HDMA输入至DDR，NPU本地DMA至L1 | 同上 | 原NPU外部DMA输出 |
| 4 | 原NPU外部DMA输入 | 同上 | NPU本地DMA至DDR，HDMA输出 |

模式1在尚未启动任何HDMA通道时运行，并单独检查两个channel enable仍为0。后续重复模式1并检查服务spawn列表只有同一存活PID；reset测试才允许一次进程替换。

代码检查：QEMU新增两个头文件checkpatch为0错误/0警告；两个仓库`git diff --check`通过；新增Python语法与文档链接/代码块检查通过。测试runtime链接器仍提示裸机映像LOAD段RWX，与现有fixture链接脚本一致，本轮未做生产镜像权限设计。

## 完整 P2 剩余项及顺序

| 后续工作 | 原因及关闭标准 |
| --- | --- |
| HDMA本地IRQ与精确状态机 | 当前STOP/ABORT可轮询，未接MCU硬件IRQ；连接已核实的中断源、mask/clear路径，并验证ISR。补完整cycle/停机/remote通知语义；当前不能把未实现的中断位当成功 |
| NPU通道级错误返回 | 当前外部错误会话fail-fast，尚未在原引擎中表示可恢复fault；应贯通busy/fence/错误归属，验证失败后其他任务继续及无成功误报 |
| inbound与完整iATU语义 | 当前保留P1软件窗口和BAR0调试镜像，仅outbound子集；实现实际BAR/inbound控制器别名与重配、权限/优先级/边界，重新按真实驱动访问验收 |
| Host文件IPC消费者 | `file-load`通知、CRC、分片/超时、`get-result`头及done协议尚未接入；应由明确的MCU运行期消费者调用真实搬运/任务，不由QEMU伪造done。FW/ROM冷启动仍为单列可选范围 |
| 扩展引擎/恢复矩阵 | 为两引擎分别补只读、撤销、跨页部分错误、并发重配、断连和reset竞争窗口；确认旧epoch不再写；补真实Tensor业务数据通路和任务/core/channel trace关联 |

当前有足够代码和证据继续上述P2开发；尚未进入P3/P4，不声明八卡大BAR/P2P/性能精度通过。

## 开发中核对与修正

- 原配置HTML使用非UTF-8字节，初次按UTF-8解析失败，改为按原字节兼容解析；没有修改手册。确认其综合参数为8读/8写通道、32入/32出region。
- 静态核对发现MCU控制器地址落在当前simu DDR0范围，单改`mmio_*`不足：补`addr_to_mem()`代理页拦截，避免RAM快速路径绕过QEMU。
- 将转换重配时的“取消通道”与“取消整个代理槽”分开，避免MCU通过代理编程iATU时提前发布该寄存器写完成。
- 拒绝未实现的descriptor中断扩展位，保留demo中明确使用的CB/TCB/LLP子集，避免把存储位等同硬件语义。
- 来宾编译曾提示sysfs路径潜在截断，扩大路径缓冲后复验；没有以警告掩盖测试失败。
