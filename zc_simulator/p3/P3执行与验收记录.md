# P3 执行与验收记录

实现日期：2026-10-28。**结论：P3 双卡软件功能闭环完成，`p3_full_exit=true`；硬件兼容性仍为独立验收范围。**

范围：两卡、每卡一个 MCU 和一个 NPU，独立共享 DDR、常驻 service/Spike、switch 本地 DDR P2P。代码位于工作区，未代用户 commit/push。

## 本轮完成

1. 在现有 endpoint 增加可选 P3 路由和显式 peer 地址域；域内错误不回退 Host，域外保留真实 requester/IOMMU。
2. 两卡使用实际 root port → switch upstream → 两个 downstream → endpoint 拓扑，按当前 BAR4 和目标 inbound 找到共享 DDR，检查源 BME、目标 MSE、桥窗口、状态、许可和长度溢出；控制区禁止作为 payload。
3. HDMA/NPU 共享同一个 peer 事务入口。两类引擎未改写成内存拷贝测试替身；原 NPU 模型及 Tensor 执行继续使用现有 Spike。
4. 固定在途请求的 fabric 签名：endpoint 配置/映射版本、会话/epoch/ready、P2P 许可、桥配置和系统映射 commit。重配置后失败旧请求，即使配置恢复也不继续旧写入。
5. 新增双卡专项和统一 P3→P2→P1 门禁、摘要清单及故障检查。生成证据加入 ignore；simulator 核心和 service 本轮未改动。

## 验收矩阵

| 场景 | 检查内容 |
| --- | --- |
| 双卡四组合 | 两方向 NPU/NPU、HDMA/HDMA、HDMA/NPU、NPU/HDMA；双向任务同时提交，跨页与非整页数据逐字节校验 |
| 独立性与常驻 | DDR 内容独立，普通任务每卡仅一次 spawn |
| 目标变化 | inbound 禁用、MSE 关闭、桥窗口关闭、BAR 移动后旧地址失败，恢复后新任务成功 |
| P2P 许可 | 两类引擎在 P2P 禁用时失败，重新启用后新任务成功 |
| Host/peer 并存 | 下游窗口互不重叠，关闭未经过的 Host 上游窗口仍能卡间访问；VT-d 打开，仅卡 B 有 Host domain；卡 A 访问 peer 成功、访问 Host IOVA 触发真实 fault；卡 B Host 读写与 A peer 同时运行 |
| 在途重配 | 两引擎 × read/write × inbound/BAR/MSE/window/policy/BME/outbound，受理后暂停、改变并恢复映射，旧请求失败且无旧 peer 写入 |
| 边界与保护 | 跨 inbound limit 失败、外侧 guard 不变、控制器和非 DDR 目标拒绝 |
| 原 Tensor | 两卡分别四组合，原模型执行结果与 P2 固定 standalone 参考逐字节一致；不称为独立数学 golden |
| 单卡断连 | 两引擎 × read/write × 断源/断目标；旧进程回收、仅故障卡一次替换、另一卡原 PID 保留、旧 backing 无晚到写入、恢复任务成功且完成不重复 |
| 系统 reset | 两引擎 × read/write；两卡均回收后替换、无虚假完成/旧写入、双向新任务恢复。没有宣称实现单 PF FLR |
| trace | 两卡/两引擎路径均为 switch_peer，Host 路径仍为 host_dma_as，目标代次可关联 |
| 回归 | 完整 P2（含 Linux Host demo、真实 Tensor、在途恢复、完整 P1）通过，manifest 验收前后相同 |

确定性暂停只用于故障注入，成功数据流不依赖暂停点。测试 Host 通过 BAR 校验非 4 字节长度时会向上对齐 32 位读取后截取，避免将现有 32 位 BAR 调试接口的末尾访问限制误判为 DMA 数据错误。

Host 注入 HDMA 故障后，将通道状态 W1C 清除再交回 MCU；否则共享 IRQ handler 可能把另一个通道的旧 ABORT 合并到新完成中。这是验收脚本对硬件状态所有权的清理，不删除故障结果或绕过 IRQ。

## 保留范围

本轮不是八卡、周期精确 PCIe、ACS/ATS/PASID、peer MMIO/Atomic、多队列生产任务协议或独立双卡 Linux 驱动验收。BAR 尺寸/属性沿用硬件信息；脚本手工配置 BAR0/BAR4，原驱动单卡场景由 P2/P1 回归覆盖。NPU 跨块任务关联使用已有 P2 集成任务编号，生产任务 ABI 另需适配；内存拓扑变化按全 fabric 保守取消，而非最小影响集。

复现与软件运行流程见 [README](README.md)。后续 P4 需要生成八卡拓扑/资源、56 个有向卡对和原驱动/任务联合验收，不能把本记录推广成八卡闭环。
