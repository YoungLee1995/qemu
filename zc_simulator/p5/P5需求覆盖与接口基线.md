| P5 工作包 | 本轮实现 | 验收入口 |
| --- | --- | --- |

| P5.2 通信接口及测试 | 自研 Python 异步 send/read/wait/barrier/reset 与 C HDMA 队列；双卡/八卡 56 卡对、Host IOMMU、错误和恢复 | `run_communication.py --cards 2/8`、`guest-communication.c` |

## 原始工具链清单的对应关系

| 原始需求章节 | 当前对应 | 明确的模型边界 |
| --- | --- | --- |
| 1—3 拓扑/组件/runtime | QEMU 一 RC/switch、八卡、IOMMU；独立 MCU/NPU 后端；P5 文件任务实际执行 | 每卡启用一 MCU/一 NPU；已有完整模型保留，未宣称全核业务覆盖 |
| 3.5、4 事务/链路 | P5 事务类型、tag、配置/消息抽象、Gen/lane；QEMU 本身处理真实配置访问 | 功能/事务层，不是全部 PCIe 协议层；posted write 无 PCIe Completion |
| 5 Switch | 真实 QEMU switch 路由，统一虚拟模型调度多端口、credit 和仲裁 | 无 TLP 位流/DLLP/链路训练；目标数据由 QEMU 检查后实际搬运 |
| 6 地址/IOMMU | requester 绑定真实 VT-d、非恒等 IOVA、权限、撤销、跨页、fault；shared DDR | 原 P2/P4 故障回归保持原口径 |
| 7 P2P | 新通信接口及原两引擎均可经真实 peer 路由；准入模型覆盖两引擎 | 无来宾 Host staging；读取 peer 数据用于结果校验不等于搬运经 Host 中转 |
| 8 DMA | 原 HDMA/NPU 描述符和 fence；软件多请求/队列，事务分片、tag、完成及错误 | 软件队列不是新增的硬件生产队列寄存器；read Completion 的乱序限于已定义的模型 |
| 9—10 流控/ordering | finite credit、backpressure、三仲裁、strict/pci_relaxed/delayed、超时和 reset | relaxed 是模型允许并发，不宣称覆盖 PCIe 所有 TC/属性组合 |
| 11 配置 | `profiles/gen4-eight.json`、逐方向链路配置、CLI | 原清单中的伪代码接口名并非必须原样提供；本项目提供对应可调用接口 |
| 12 测试 | 模型专项、双/八卡通信、Linux 驱动、任务包、错误/reset 和完整历史矩阵 | IRQ60/诊断区/FLR按明确软件接口验收；没有单 hart 硬件 reset 宣告 |
| 13 Trace/验收 | 实际 QEMU `p2_host`/route trace + sidecar token/slot/session/epoch + packet/request/链路统计 | 实际内存成功与虚拟准入时间分开；CPU/PCIe 不共用周期时间轴，未提供物理性能校准 |
| 14 排除项 | 基础通信由本项目实现；未实现 CCL/collective/完整算子库 | 符合原排除范围 |

## 接口事实与仿真实现选择

- 已确认 BAR：4 MiB/32 MiB/32 GiB，64 位，前两组 non-prefetch、最后一组 prefetch。
- demo 依据：HDMA 通道与描述符字段、ATU 地址处理、文件通知/CRC/结果头、原 Linux 驱动。
- 本项目新增：任务包 manifest/mode 5、Python/C 软件通信接口、异步 fabric 准入协议、事务/流控模型、可选 FLR。
- 已有软件选择继续保留：MCU IRQ 60、NPU per-hart 诊断区；未将其改称从手册证实的硬件编号/CSR。
- 性能参考采用独立理论公式，24 B framing 是显式模型参数口径；物理硬件校准标记保持 false，不需要外部资料即可复现软件模型验收。

P5 软件阶段的通过情况以 [执行记录](P5执行与验收记录.md) 为准。完整协议一致性认证、物理芯片 register-by-register 认证和统一 CPU/PCIe 周期仿真不包含在本软件模型结论中。
