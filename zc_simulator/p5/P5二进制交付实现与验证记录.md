# P5 Linux 二进制交付实现与验证记录

2026-10-29。本轮只调整 QEMU 项目中的启动、打包和文档，不改动 simulator 源码。目标是交付 QEMU 源码及本目录下的 simu 运行包后，不依赖外部 simulator/experiments 源码树运行现有 Linux 双卡/八卡链路。

## 实现

- `run_linux.py` 默认 `--runtime auto`。检测 `simulator/riscv-isa-sim/spike_main/spike.cc`，存在则编译/发布新包，不存在则校验并加载 `zc_simulator/simu/current`。
- 新增 `linux_bundle.py`：编译 Spike、firmware、P5 runtime、适配 Host 模块与双卡/八卡来宾程序；复制内核、配置、生命周期/协议/fabric 服务，生成 SHA256 manifest。
- 包内含预生成双卡/八卡 initramfs，预编译运行无需 gcc、make 或 RISC-V 编译器，也不读取 stage1 rootfs/kernel 和 simulator 源码。
- `BundlePlatform` 复用 P4 拓扑与地址布局、P5 fabric/FLR 开关，用包内预编译镜像和服务生成全新 backend 配置。启动时重新计算实际绝对路径、配置 SHA256；QEMU 可安装在不同目录名下。
- 发布使用版本目录和原子 `current` 链接切换；构建失败不回退假成功、不破坏已有包；每次加载校验所有载荷。模型副本仅 strip debug，原 Spike 构建文件不变。
- `--runtime source/prebuilt` 用于强制选择；`--prepare-only` 只生成/验证包，不启动 QEMU。
- 生成载荷由 `simu/.gitignore` 忽略，说明文档跟踪。交付必须额外复制/归档载荷和链接，普通 git push 不含二进制。
- 来宾任务、四种 DMA 模式、文件 IPC、队列和结果判据保持原链路；补充显式检查 `P5_BASE_PASS`，避免只确认最后的 C 库结果。

## 交付范围

约 31 MiB 的初始运行包支持本次 `run_linux.py` 的双卡/八卡功能，不宣称 P0–P5 全部历史脚本均可离线复现。未重跑完整 P5/P4/P3/P2/P1 门禁；先前阶段出口为历史证据。实际二进制、内核、配置摘要见各轮 `bundle.json` 和运行包 `manifest.json`。

运行环境仍需 Linux x86-64、Python 3 及 Spike 的动态库；接收方须正常构建并提供 QEMU 自身 ROM/BIOS 资源。独立任务包生成脚本和 Tensor golden 输入未包含在本 Linux 运行包中。

使用方法与交付命令见 [simu 运行包说明](../simu/README.md)。
