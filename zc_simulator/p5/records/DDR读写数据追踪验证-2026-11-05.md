# DDR 读写与数据追踪验证（2026-11-05）

新增 `native/ddr-roundtrip.c`，独立配置并恢复 inbound region 0，Host 使用 32 位 BAR4 访问对 DDR0 0x20028000 起 64 字节进行三轮写读。默认模型 DDR 映射保持不变。

`hw/misc/zc-pcie-p2-engine.h` 新增可选 inbound 访问日志，使用现有 `p2-trace` 与 `interaction-log` 控制。记录 Host CPU 来源、时间、card/session/epoch、读写方向、BAR 偏移、总线地址、inbound region、转换后设备地址、32 位数据及接受/拒绝结果。操作方表示 CPU MMIO 路径，来宾 PID 由 Host 程序记录。日志沿用 QEMU 交互文件，包含 JSON 行和原有文本行；解析时筛选 bar_inbound。

实测：

- `ninja -C build -j4 qemu-system-x86_64` 成功；Host 测试 `gcc -O2 -Wall -Wextra -Werror` 通过。
- 隔离 Ubuntu 系统盘 `/tmp/zc-tutorial-fresh-20261103/fixed-state`、SSH 2226、RDP 13393；测试未操作正在运行的默认 state 实例。
- 实际 Host 输出 `DDR_ROUNDTRIP_PASS rounds=3 bytes_per_round=64 mismatches=0`。
- 解析 QEMU 日志获得 48 笔写、48 笔读，全部地址和数据相同且 result=ok。首地址 0x20028000，首数据 0x12345678。
- 程序恢复原先关闭的窗口后，再读同一地址返回 `0xffffffff`，日志记录 `result=rejected`、`region=-1`、`device_addr_valid=false`；随后正常关闭隔离 Ubuntu 并退出测试 Spike。
- 证据 `/tmp/zc-ddr-debug/host.log`、`qemu-spike-card0.log`、`qemu-console.log`；日志时间字段为 Unix 微秒。

此测试确认当前环境中的正常 inbound 往返，不证明同事的具体故障已复现。调试前停止其他设备用户，确认目标页空闲；程序退出恢复窗口，测试数据保留。未覆盖 MCU/NPU 对共享 DDR 的逐条访问、DMA payload 或所有特殊 BAR 寄存器。
