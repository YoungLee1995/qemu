# P5 执行与验收记录

日期：2026-10-29。输入按用户确认冻结为已有 pcie-demo、host-demo、simulator 和任务素材；没有额外外部资料前置条件。本轮通信接口、任务包、runtime 扩展及事务模型由项目实现。

## 实现

1. 新增 simulator `tools/p5/`：虚拟时间 fabric、P/NP/Cpl credit/仲裁、非阻塞 sidecar 服务、异步软件队列、C 通信接口、任务包校验、参数示例及 P5 runtime。
2. QEMU 新增 `p5-fabric-socket`，HDMA/NPU 外部 DMA 可异步等待模型准入；pending 期间保持事件循环推进，4 秒实时时间 watchdog 防止失联永久等待。服务失败报错而不静默绕过。
3. 新增 `p5-flr` 标准 function reset，可取消在途操作并只重建目标后端；slot token/session/epoch 防止旧 grant 被复用。
4. 平台仅新增可选 runtime 目录，P4 默认软件保持原路径；P5 mode 1—4 兼容，新增 mode 5 连接 demo 文件传输和真实 NPU Tensor 执行/结果返回。
5. 新增单点构建/回归入口、独立协议/队列测试、理论校准、任务/通信/IRQ/错误/断连、Linux C 通信联合测试和原 P4 全回归。

## 调试中发现并修复的问题

- Linux BAR 模型只支持 32 位访问，首轮 C 通信测试通过字节指针写 payload 导致数据校验失败；改为按 32 位发布/读取，仍检查 517 字节非整包长度。
- 首轮 FLR 后后端已 ready，但标准 QEMU PCI reset 清除了 function BAR/command，旧 MMIO 地址读不到 ready；复位调用端只恢复该 function 的资源，再恢复 ATU 后任务通过。
- 协议模型验证 Completion requester/tag 后才调用实际读数据回填，防止错误 tag 产生内存副作用；read tag 只在所有 split Completion 返回后释放。
- socket 断连清除半帧接收状态；slot 取消及 token 单调递增防止 reset 后旧回复误配。fabric 失联测试保留原 Spike，明确失败、无旧写入，服务重启并 FLR 后再执行成功。

## 验收口径

物理硬件校准为 false；IRQ 60 和 NPU 诊断区是明确的软件接口。P5 自研任务/队列/通信 API 不冒充额外取得的生产接口。虚拟时间准入规划、实际 QEMU 内存提交、CPU 墙钟三者分开统计。具体范围、路径和限制见 [README](README.md) 与 [需求覆盖](P5需求覆盖与接口基线.md)。
