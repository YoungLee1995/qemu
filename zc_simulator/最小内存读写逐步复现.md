# 最小内存读写逐步复现与日志追踪

本文只验证一笔 Host → PCIe BAR4 → inbound → Spike DDR 的 32 位写入和读回。每一步都给出启动命令、预期输出和日志位置。通过已有通用工具 `pcie-mmio.py BDF BAR 偏移 [写入值]` 逐条访问：省略值为读，提供值为写。结束时用命令恢复窗口；测试字保留在 DDR。默认镜像的测试地址为 `0x20028000`，自定义固件需确认该地址空闲。

## 环境准备

先完成 QEMU 构建、Ubuntu 镜像下载、`zc_simulator/desktop/prepare.py` 和首次 Ubuntu 初始化。旧 Ubuntu/QEMU 应先正常关机并释放系统盘、2222/13389 端口；Spike 在其原终端按 Ctrl+C 退出。以下准备命令在 QEMU 仓库根目录执行；测试过程中不要同时运行其他会改写 inbound 窗口的 Host 程序。

```bash
cd /workspace/GIT/pcie_qemu/qemu
ninja -C build -j4 qemu-system-x86_64
mkdir -p /tmp/zc-ddr-step-demo
cp zc_simulator/simu/current/images/mcu.bin /tmp/zc-ddr-step-demo/mcu.bin
cp zc_simulator/simu/current/images/npu.bin /tmp/zc-ddr-step-demo/npu.bin
cat > /tmp/zc-ddr-step-demo/firmware.cfg <<'CFG'
runtime_func:1
pc_num:2
[1, 0x40000000, ./mcu.bin]
[16, 0x4000000000, ./npu.bin]
ddr_input_num:0
ddr_output_num:0
l1buf_input_num:0
l1buf_output_num:0
CFG
cp zc_simulator/native/pcie-mmio.py zc_simulator/desktop/state/share/pcie-mmio.py
```

## 第 1 步：启动 Spike

终端 A：

```bash
cd /workspace/GIT/pcie_qemu/qemu
spike_repo=$(pwd)
step_work=/tmp/zc-ddr-step-demo
step_digest=$(sha256sum "$step_work/firmware.cfg" | cut -d ' ' -f1)
cd "$step_work"
"$spike_repo/zc_simulator/simu/current/bin/spike" \
  --pcie-socket "$step_work/card0.sock" \
  --pcie-config-sha256 "$step_digest" \
  --pcie-card 0 \
  --pcie-log "$step_work/spike-qemu-interaction.log" \
  --isa=rv64imafdcv_zvl512b_zve32d_zfh_zvfh_zfbfmin_zvfbfmin_zba_zbb_zbs_zicond \
  --runtime-func "$spike_repo/zc_simulator/simu/current/images/firmware.riscv" \
  -cfg "$step_work/firmware.cfg" \
  > "$step_work/spike-console.log" 2>&1
```

保持终端 A 运行。终端 B 查看：

```bash
tail -F /tmp/zc-ddr-step-demo/spike-console.log
```

QEMU 接入前看到 `SPIKE_WAIT_QEMU`；连接后看到 `SPIKE_QEMU_CONNECTED`。Spike 会话及心跳在 `/tmp/zc-ddr-step-demo/spike-qemu-interaction.log`：

```bash
tail -F /tmp/zc-ddr-step-demo/spike-qemu-interaction.log
```

## 第 2 步：启动 QEMU

终端 B 启动 Ubuntu。`p2-trace=on` 开启逐笔 BAR 追踪，`interaction-log` 保存 QEMU 与 Spike 的交互日志：

```bash
cd /workspace/GIT/pcie_qemu/qemu
qemu_repo=$(pwd)
step_work=/tmp/zc-ddr-step-demo
step_state="$qemu_repo/zc_simulator/desktop/state"
step_digest=$(sha256sum "$step_work/firmware.cfg" | cut -d ' ' -f1)
flock -n "$step_state/desktop.lock" \
"$qemu_repo/build/qemu-system-x86_64" \
  -L "$qemu_repo/pc-bios" -machine q35 -accel tcg -cpu max -m 4G -smp 4 \
  -nodefaults -display none -serial stdio -monitor none -no-reboot \
  -global q35-pcihost.pci-hole64-size=512G \
  -device intel-iommu,intremap=on,caching-mode=on \
  -drive "file=$step_state/ubuntu-24.04-desktop.qcow2,format=qcow2,if=none,id=osdisk" \
  -device virtio-blk-pci,drive=osdisk,addr=4,iommu_platform=on,disable-legacy=on \
  -drive "file=$step_state/seed.iso,format=raw,media=cdrom,readonly=on" \
  -netdev user,id=net0,hostfwd=tcp:127.0.0.1:2222-:22,hostfwd=tcp:127.0.0.1:13389-:3389 \
  -device virtio-net-pci,netdev=net0,addr=5,romfile=,iommu_platform=on,disable-legacy=on \
  -fsdev "local,id=share,path=$step_state/share,security_model=none" \
  -device virtio-9p-pci,fsdev=share,mount_tag=hostshare,addr=6,iommu_platform=on,disable-legacy=on \
  -device pcie-root-port,id=rp,addr=2,chassis=1 \
  -device x3130-upstream,id=sw,bus=rp \
  -device xio3130-downstream,id=ds0,bus=sw,addr=1,chassis=2 \
  -device "zc-pcie-p1,id=ep0,bus=ds0,addr=0,p2=on,p2-trace=on,card-id=0,backend-socket=$step_work/card0.sock,config-sha256=$step_digest,interaction-log=$step_work/qemu-spike-card0.log" \
  > "$step_work/qemu-console.log" 2>&1
```

QEMU 启动后，终端 C 查看：

```bash
tail -F /tmp/zc-ddr-step-demo/qemu-console.log
```

QEMU 连接日志：

```bash
tail -F /tmp/zc-ddr-step-demo/qemu-spike-card0.log
```

两侧交互日志应出现 type `1/2`、`3/4`、`5/6` 握手，随后 type `14/15` 心跳。`spike-console.log` 同时出现 `SPIKE_QEMU_CONNECTED`。这一步确认传输连接；测试读写时才会出现 `bar_inbound`。

## 第 3 步：进入 t100，确认设备

等待 `qemu-console.log` 出现 SSH 服务启动信息后，在终端 C 执行；启动期间连接超时可继续观察启动日志，再重试：

```bash
cd /workspace/GIT/pcie_qemu/qemu
ssh -i zc_simulator/desktop/state/ssh_key \
  -o IdentitiesOnly=yes -o StrictHostKeyChecking=accept-new \
  -o UserKnownHostsFile=zc_simulator/desktop/state/known_hosts \
  -p 2222 t100@127.0.0.1
```

密码为 `t100`（使用密钥时不需要输入）。进入 Ubuntu 后：

```bash
lspci -Dnn -d 16c3:abcd
bdf=0000:03:00.0       # 按 lspci 的实际 BDF 修改
sudo python3 /mnt/hostshare/pcie-mmio.py "$bdf" 0 0x0
sudo python3 /mnt/hostshare/pcie-mmio.py "$bdf" 0 0x8
```

预期设备标识为 `0x5a435031`，传输状态为 `1`。若 BDF 不同，只替换后续命令中的 `bdf`。

## 第 4 步：逐条配置窗口、写入和读回

以下在 **t100 的 Bash 终端**逐块执行。用 `script` 保存命令和输出；`mmio` 只是现有通用命令的缩写。换 case 时修改 BDF、BAR、偏移和数据即可。

```bash
script -q -f /tmp/ddr-command.log
bdf=0000:03:00.0
mmio() { sudo python3 /mnt/hostshare/pcie-mmio.py "$bdf" "$@"; }
```

**4.1 保存原 inbound region 0 的九个寄存器。** 输出及原值保存到 Host 日志，稍后恢复时使用 `saved` 数组；请在同一个 Bash 会话完成：

```bash
saved=()
for i in {0..8}; do
  value=$(mmio 0 $((0x300100 + i * 4))) || break
  echo "$value"
  saved[i]=${value##* = }
done
test "${#saved[@]}" -eq 9 && echo SAVE_OK
```

看到 `SAVE_OK` 后继续。BAR0 配置访问的证据是上述命令输出；数据访问的 `bar_inbound` 日志在后续写读时产生。

**4.2 获取 BAR4 实际分配地址，计算窗口范围。**

```bash
read bar4_start bar4_end bar4_flags < <(sed -n '5p' "/sys/bus/pci/devices/$bdf/resource")
bus_base=$((bar4_start + 0x20000000))
bus_limit=$((bus_base + 0x1ffff))
printf 'BAR4=%#x inbound_base=%#x inbound_limit=%#x target=0x20010000\n' "$bar4_start" "$bus_base" "$bus_limit"
```

基址由 PCI 分配，使用命令实际输出。窗口将 BAR4 `+0x20000000` 映射到 DDR0 `0x20010000`，长度 128 KiB。

**4.3 先禁用窗口，再写各字段，最后启用。** 每条命令应输出 `WRITE BAR0+... <- ...`，确认后执行下一条：

```bash
mmio 0 0x300104 0                          # CTRL2：禁用
mmio 0 0x300100 0                          # CTRL1：内存地址匹配
mmio 0 0x300108 $((bus_base & 0xffffffff))  # BASE_LOW
mmio 0 0x30010c $((bus_base >> 32))         # BASE_HIGH
mmio 0 0x300110 $((bus_limit & 0xffffffff)) # LIMIT
mmio 0 0x300114 0x20010000                 # TARGET_LOW
mmio 0 0x300118 0                          # TARGET_HIGH
mmio 0 0x300120 0                          # UPPER_LIMIT（本例未启用）
mmio 0 0x300104 0x80000000                 # CTRL2：启用
mmio 0 0x300104                            # 读回应为 0x80000000
```

**4.4 在外层容器另开日志终端，保持逐笔追踪：**

```bash
tail -n 0 -F /tmp/zc-ddr-step-demo/qemu-spike-card0.log | \
  grep --line-buffered '"event":"bar_inbound"'
```

**4.5 回到 t100 写一个 32 位字。** 执行后先查看外层新增的 QEMU 日志，再继续读：

```bash
mmio 4 0x20018000 0x12345678
```

Host 输出 `WRITE BAR4+0x20018000 <- 0x12345678`；QEMU 新增 `operation=write`、`value=0x12345678`、`device_addr=0x20028000`、`result=ok`。

**4.6 读同一个地址。**

```bash
mmio 4 0x20018000
```

Host 输出 `BAR4+0x20018000 = 0x12345678`；QEMU 新增 `operation=read`，地址、值与前一笔写一致。

**4.7 改写数据并再次读回。** 分别执行，每条都查看新增日志：

```bash
mmio 4 0x20018000 0xa5a55a5a
mmio 4 0x20018000
```

读回应为 `0xa5a55a5a`，对应两行 QEMU 日志的 `value` 也应为 `0xa5a55a5a`。四笔的 BAR 偏移均为 `0x20018000`，设备地址均为 `0x20028000`。

**4.8 恢复原窗口。** 先禁用，再恢复其他字段，最后恢复 CTRL2：

```bash
mmio 0 0x300104 0
for i in 0 2 3 4 5 6 7 8; do
  mmio 0 $((0x300100 + i * 4)) "${saved[i]}"
done
mmio 0 0x300104 "${saved[1]}"
```

即使写读失败也应恢复窗口。测试数据保留；如要更换测试地址，在窗口范围内替换 BAR4 偏移即可。例如 `0x20018004` 对应 DDR0 `0x20028004`，地址必须 4 字节对齐。访问其他设备内存区时，按其地址范围修改 TARGET、窗口长度和 BAR 偏移。

```bash
exit   # 单独执行：退出 script 记录会话，回到原 t100 shell
```

看到 `Script done` 并返回原 t100 提示符后，再执行：

```bash
sudo cp /tmp/ddr-command.log /mnt/hostshare/ddr-command.log
```

## 第 5 步：逐笔对照日志

在外层容器另开终端：

```bash
# QEMU 对每次 BAR 访问的转换、数据和结果
grep '"event":"bar_inbound"' /tmp/zc-ddr-step-demo/qemu-spike-card0.log

# 只看写入
grep '"event":"bar_inbound"' /tmp/zc-ddr-step-demo/qemu-spike-card0.log | grep '"operation":"write"'

# Host 侧命令、请求顺序和读回结果（结束后复制的完整记录）
cat /workspace/GIT/pcie_qemu/qemu/zc_simulator/desktop/state/share/ddr-command.log
```

共享目录中的 Host 日志是上一步复制的快照。测试进行中要实时看 Host 日志，在另一个 t100 终端执行 `tail -F /tmp/ddr-command.log`；外层实时查看数据访问使用上面的 `qemu-spike-card0.log`。`tail -F` 会持续等待新内容，按 Ctrl+C 结束查看。如果出现 `inotify cannot be used, reverting to polling`，表示已改用轮询，日志仍可继续读取。

每笔 QEMU 记录类似：

```json
{"event":"bar_inbound","time_us":1793843000000000,"actor":"host_cpu_mmio","operation":"write","bar":4,"bar_offset":"0x20018000","bus_addr":"0xc020018000","region":0,"device_addr_valid":true,"device_addr":"0x20028000","size":4,"value":"0x12345678","result":"ok"}
```

读记录的 `value` 是 QEMU 返回给 Host 的实际数据；写记录的 `value` 是 Host 提交的数据。用 `time_us`、同地址的操作顺序和 Host 日志对照，检查 `bar_offset`、`device_addr`、`value` 是否一致。`actor=host_cpu_mmio` 表示来宾 CPU 通过 PCIe BAR 发起；Host 日志保存了每条命令及其输出，可按访问顺序对照。

如果读回错误，优先保存以下日志文件再分析：

```text
zc_simulator/desktop/state/share/ddr-command.log
/tmp/zc-ddr-step-demo/qemu-spike-card0.log
/tmp/zc-ddr-step-demo/qemu-console.log
/tmp/zc-ddr-step-demo/spike-console.log
```

重点比较错误读对应的 QEMU `value`、`device_addr` 和前一笔写入值。如果 `result=rejected` 或 `device_addr_valid=false`，说明 inbound 窗口、地址范围或设备状态检查未通过；如果两笔都是 `result=ok` 但读值改变，则检查设备固件是否在写入后覆盖了该 DDR 地址。

## 第 6 步：结束实验

测试正常完成后，在 **t100 内**执行：

```bash
sudo poweroff
```

等待 QEMU 原启动终端返回，然后在 Spike 原启动终端按 `Ctrl+C` 结束监听。保留 `/tmp/zc-ddr-step-demo/` 和 `state/share/ddr-command.log`。
