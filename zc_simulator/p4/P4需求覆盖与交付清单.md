# P4 需求覆盖与交付清单

执行口径遵循 [内部PCIe互联平台分阶段实现方案](../内部PCIe互联平台分阶段实现方案.md) 的首期功能范围。工具链原始需求中的完整 TLP、credit/buffer/backpressure、链路仲裁及带宽时延模型属于后续协议/性能阶段，不将 QEMU 墙钟统计替代这些能力。

| 首期条目 | 实现与验收入口 | 边界 |
| --- | --- | --- |
| 一 RC、一 switch、八 EP 和独立后端 | `cluster_platform.py`、`run_cluster.py`、`run_linux.py` | 一个 Host socket；Linux 四逻辑核以容纳 256 MSI-X 向量 |
| 真实尺寸 BAR、桥窗口、原驱动 probe | qtest 探测掩码、Linux 24 BAR dump/不重叠检查、原 host-demo 驱动八节点 | 不是八个空 EP 或仅枚举测试 |
| 实际 MCU/NPU 初始化与常驻任务 | 八个 ready、四组合、普通任务 PID 不变 | 启用 MCU/NPU 各 8，创建容量另列；不要求运行旧可选 32 NPU 目标 |
| 两类引擎 56 有向卡对/并发 | 四组合全 56 对，七轮八卡任务；trace 按引擎核对全卡对 | linked 多目标链表的最小影响集隔离未验收 |
| Host IOMMU / domain 隔离 | 八个 requester 相同 IOVA→不同 GPA、真实 VT-d fault、只读与撤销 | peer 不走 Host IOMMU、不落 Guest Host staging |
| 混合 Host/peer 访问 | 八 NPU peer + 八 HDMA Host 写并存，再进行八 Host 读 | 不是性能/仲裁精度认证 |
| 原模型任务 | 八卡四组合真实 Tensor、Host/peer 数据、文件 CRC/结果、真实 MCU IRQ 和 MSI-X | Tensor 比较固定 standalone 模型参考，独立数学 golden 差异沿用 P2 |
| 故障隔离和恢复 | 两引擎读写 × 源/目标断连、runtime crash、BAR/inbound/桥窗口重配；六卡在途不受影响 | 普通通道按相关卡隔离；链表模式保守取消 |
| timeout / 通道停止 / 系统 reset | NPU 代理 5 秒超时触发原错误/服务恢复、通道停止、八卡系统 reset 后恢复 | NPU timeout 当前按整后端致命错误恢复；没有伪造单 PF FLR/单 hart reset ABI |
| 固定输入重复运行 | mode 1 全 56 对相同输入三轮通过，输入摘要一致 | 不宣称墙钟/调度 trace 位级确定 |
| 原驱动/任务联合层 | Linux 原 host-demo 驱动，32 Host + 224 peer 任务、八卡文件 IPC 与 IRQ | 继续复用已适配 demo；生产工具链多队列文件格式、外部通信库另列 |
| 历史回归 | 完整 P3→P2→P1，单 die/原指令/fence/本地 IRQ 既有路径 | 验收按各原专项已定义范围，未把历史限制改写成硬件已确认 |

交付文件：

- QEMU 源码：`hw/misc/zc-pcie-p1.c`、`zc-pcie-p2.h`、`zc-pcie-p2-engine.h`、`zc-pcie-p3-route.h` 的 P4 增量。
- 自动布局/启动/清理：`cluster_platform.py`、`launch.py`；支持 1/2/8 卡。
- 八卡原模型验收：`run_cluster.py`。
- 原驱动 guest 集成：`guest-cluster.c`、`run_linux.py`；原驱动构建复用 `../p1/build_host_demo.py` 和已锁定补丁。
- 三层统一门禁与摘要：`run_all.py`。
- 文档：本清单、[README](README.md)、[执行记录](P4执行与验收记录.md)、simulator 的 SIM-007 集成记录。

源码/脚本随仓库交付；生成的镜像、日志、socket 和 evidence 按 ignore 保存在本地，可按固定入口重新生成。工作区改动尚未代用户提交或推送。

硬件兼容性仍单列：物理 MCU IRQ 号、硬件 NPU 错误 CSR、生产任务文件/多队列 ABI、完整 DWC 高级特性、FLR 和独立数学参考。八卡软件功能出口与上述兼容性/协议性能扩展分别判断，不把后续阶段作为功能出口的永久阻塞，也不删除差异。
