# P4 执行与验收记录

日期：2026-10-28。范围：首期八卡软件功能平台。最终统一门禁通过，`p4_full_exit=true`；P4 软件功能出口已关闭。硬件兼容性出口仍为 `false`，不扩大本轮验收范围。

## 实现内容

1. 自动生成八端口拓扑、完整三组 BAR、互不重叠的下游窗口、BDF、card ID、服务/socket 和 peer 域；BAR4 总范围由双卡 64 GiB 扩到八卡 256 GiB。
2. 新增可复用平台类、常驻启动入口、八卡原模型专项、Linux 原驱动八卡 guest 工作负载及统一门禁。每卡独立共享 backing/进程，普通任务保持原 PID。
3. 新增 `p4-isolation`：普通 HDMA 按已接受的远端地址固定相关卡，NPU 按源 outbound 固定可达 peer，MemoryListener 将实际 BAR decode 变化归属到目标卡；不再因无关卡故障取消普通在途请求。
4. 覆盖四组合全 56 对、八卡 Host 同 IOVA/domain 隔离、Host/peer 并存、八卡真实 Tensor、相同输入三轮重复、两引擎读写故障隔离、NPU 超时、通道停止、八卡 reset。
5. 原 host-demo 驱动在 Linux 中实际 probe 八卡，检查 24 个真实 BAR，完成 32 Host 和 224 peer 任务、八卡 CRC/文件结果/本地 IRQ/MSI-X。
6. 归档覆盖/trace/版本摘要，采样宿主 CPU、RSS、虚拟映射和运行时间。文档记录实际创建/启用核数、接口影响及能力差异。

## 代码与接口

- `zc-pcie-p1.c`：新增 P4 opt-in 参数、每卡 map generation、MemoryListener region add/del 归属；未启用 P4 时保持 P3 策略。
- `zc-pcie-p2.h`：通道新增 `route_addr`。

## 失败定位与收敛

- 首轮 Linux 一个逻辑核无法为八卡每卡 32 个 MSI-X 分配全部向量，后两卡 probe 失败。保持原驱动，采用一个 Host socket/四逻辑核后八卡 probe、任务和 IRQ 通过。没有削减设备 BAR/向量表或跳过失败卡。
- guest 中 `realpath` 使用小于 PATH_MAX 的栈缓冲会触发 glibc fortified 检查；改为 PATH_MAX 缓冲，随后按 sysfs 父设备匹配每卡字符节点，不依赖目录顺序/minor 假设。
- P3 的全 fabric 取消策略不满足 P4 无关卡在途保持要求，新增 opt-in 的相关源/目标作用域并验证实际数据和进程隔离；链表动态多目标仍公开保守策略。

- 独立常驻启动的相对 `--work` 路径会导致后端从工作目录再次解析相对镜像路径，首轮 ready 超时；统一将工作目录解析为绝对路径后，八卡 ready、控制 socket 交出和有界退出已实际通过，证据为 `evidence/launch-relative-fixed`。

## 宿主资源成本

八卡专项本轮约 59.15 秒；子进程累计用户态 CPU 89.33 秒、内核态 9.52 秒；最大单子进程 RSS 229988 KiB。结束前一次进程 RSS 点采样简单相加约 333896 KiB，包含共享映射重复计数，不等于独占物理内存峰值。详细数据在该轮 `resources.json`。

每卡 backing 虚拟容量 257 GiB，八卡 2056 GiB；BAR4 可见窗口合计 256 GiB。稀疏 memfd 按触页分配，不能按虚拟容量推断物理内存占用，也不能从墙钟/CPU 耗时推断真实 PCIe 带宽。

## 保留范围与后续

首期每卡启用一个 MCU、一个 NPU：八卡共 16 个 runtime hart；模型另创建 firmware/inactive hart，总 processor 对象 56，详见 README。没有宣称八卡启用 32 个 NPU 或完整多 die。

生产硬件兼容性、真实冷启动、单 PF FLR/单 hart reset ABI、生产多队列任务文件和外部通信库仍按既有边界分别记录。完整 TLP/tag/credit、backpressure、带宽竞争/协议时序属于后续阶段。这些后续项不阻塞已完成的 P4 软件功能出口，仍按独立范围记录。
